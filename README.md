# public-skills-repo

Claude Code / Claude Cowork에서 쓰는 **공개 스킬 모음**입니다. 직접 만들어 쓰면서 다듬은 것 중 일반적으로 쓸 만한 것만 골라 공개합니다.

## 수록 스킬

| 스킬 | 무엇을 하나 | 언제 걸리나 |
|---|---|---|
| [**work-harness**](skills/work-harness) | 글·문서·기획 산출물의 품질을 출력 전에 자체 검증 | 보고서·이메일·요약·기획 메모를 쓸 때 |
| [**dev-evidence-gate**](skills/dev-evidence-gate) | 코드 작업의 완료 판정을 증거로 강제 | 앱·사이트·스크립트를 만들거나 고칠 때 |

두 스킬은 짝입니다. 하나는 **읽는 사람이 받는 결과물**을, 다른 하나는 **동작해야 하는 결과물**을 책임집니다.

---

## 왜 필요한가

AI에게 일을 시키면 이런 일이 반복됩니다.

- 분량을 5줄로 지정했는데 10줄이 온다
- "매우 효과적이고 혁신적인" 같은 AI 티가 나는 문장이 섞인다
- 앞 문단에선 추천하다가 뒤 문단에선 비추천한다
- 코드를 고쳐놓고 "테스트가 통과했으니 완료"라고 한다. 실제로 켜보면 안 된다
- 검증하느라 띄운 서버가 그대로 살아있다

전부 **출력 직전에 스스로 점검하는 기준이 없어서** 생기는 일입니다. 이 스킬들은 그 기준을 "예 / 아니오"로 답할 수 있는 판정 질문으로 만들어 매번 통과시킵니다.

## 설치

### Claude Code

저장소를 받아 스킬 폴더에 연결합니다.

```bash
git clone https://github.com/hoyamoon/public-skills-repo.git
cd public-skills-repo

# 개인 전역 스킬로 쓰기 (모든 프로젝트에서 사용)
mkdir -p ~/.claude/skills
ln -s "$(pwd)/skills/work-harness" ~/.claude/skills/work-harness
ln -s "$(pwd)/skills/dev-evidence-gate" ~/.claude/skills/dev-evidence-gate
```

특정 프로젝트에서만 쓰려면 `~/.claude/skills` 대신 그 프로젝트의 `.claude/skills`에 연결합니다.

심링크 대신 폴더째 복사해도 됩니다. 다만 심링크로 걸어두면 `git pull` 한 번으로 업데이트가 반영됩니다.

설치 확인은 Claude Code에서 `/skills`를 입력하거나, "하네스 검증 기준 알려줘"라고 물어보면 됩니다.

### Claude Cowork (데스크톱)

Cowork는 폴더 연결 대신 `.skill` 파일 업로드 방식입니다.

```bash
cd skills
zip -r work-harness.skill work-harness
zip -r dev-evidence-gate.skill dev-evidence-gate
```

만들어진 `.skill` 파일을 **Cowork > Customize > Skills**에서 업로드합니다.

## 쓰는 법

설치하면 상황에 맞을 때 자동으로 걸립니다. 명시적으로 부르고 싶으면 이렇게 말하면 됩니다.

**work-harness**
- "이 초안 하네스로 점검해줘"
- "금지어 남아있는지 확인해줘"
- "이 작업 규모 판정해줘" (S 단발형 / L 장문형 / D 지속개발형)

**dev-evidence-gate**
- "이번엔 빡세게 검증하고 완료해줘"
- `ulw` 또는 "울트라워크" (전체 적용 강도로 실행)
- "완료 전에 증거 게이트 통과시켜줘"

### 직접 만든 스킬에서 상속하기

본인 스킬 본문에 한 줄만 넣으면 이 규율을 물려받습니다.

```markdown
검수는 work-harness §4를 따른다.
코드 산출물의 완료 판정은 dev-evidence-gate를 적용한다.
```

## 무엇이 들어 있나

### work-harness

- **하네스 체크리스트 H1~H6** — 요청 커버리지 / 즉시 사용 가능성 / 일관성 / 압축 내성 / 정밀도 / 사실 정합성. 각 항목이 판정 질문과 실패 신호를 가집니다.
- **한국어 공통 금지어 6종** — 과장형 형용사, 모호한 부사, 근거 없는 단정, AI 흔적 상투구, 추상명사 남용, 동의어 중복. 그리고 긴 하이픈(`—`) 금지 규칙.
- **컨텍스트 3레이어 분리** — 장기 작업에서 "사실성 우선" 같은 원칙이 "이번엔 임팩트 있게"라는 요청에 흡수되어 희석되는 것을 막습니다.
- **작업 규모 3급 분류** — S(단발) / L(장문) / D(지속개발)를 판정하고 규모에 맞는 분할·위임 전략을 씁니다.
- **위임 계약 7요소** — 서브에이전트에 일을 넘길 때 빠뜨리면 안 되는 항목들.

### dev-evidence-gate

- **시나리오 계약** — 코드를 쓰기 전에 통과 조건을 이진 관찰 가능한 형태와 리터럴 명령으로 확정합니다. "동작해야 함"은 조건이 아닙니다.
- **증거 2종** — 구현 전에 실패를 캡처하는 RED→GREEN 증명 + 실제 표면(브라우저·curl·터미널)에서 직접 써보는 수동 QA.
- **정리 영수증** — 검증하느라 띄운 프로세스·포트·임시파일을 껐다는 기록. 남아 있으면 완료가 아닙니다.
- **정지 규칙** — 완료 조건이 성립하면 즉시 멈춥니다. 그 뒤의 추가 검증·보너스 리팩터링은 성실함이 아니라 범위 초과입니다.
- **승인 편향 리뷰어** — 리뷰어는 blocker만 찾고(최대 3건), 애매하면 승인합니다. 완벽주의 리뷰어가 만드는 무한 수정 루프를 막습니다.
